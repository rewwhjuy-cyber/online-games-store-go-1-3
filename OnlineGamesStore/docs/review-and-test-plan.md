# Code review и тест-план

## Проверяемые дефекты и меры

| Риск | Исправление в проекте | Проверка |
|---|---|---|
| SQL injection через sortBy | whitelist фиксированных SQL-фрагментов | sortBy произвольный → безопасная сортировка по умолчанию |
| Подмена цены/итога клиентом | API заказа не принимает total; расчёт из БД | сумма в запросе не используется |
| Отрицательные цены/остатки | CHECK в БД и валидация HTTP | миграции и некорректный POST |
| Двойная продажа последней копии | транзакция и `FOR UPDATE` по games | параллельные заказы на один остаток |
| IDOR заказа | проверка user_id в сервисном HTTP пути | CUSTOMER A запрашивает заказ B → 404 |
| Повторное использование refresh | хеш в БД, revoke+rotate транзакционно | повтор старого refresh → 401 |
| Массовое назначение роли | регистрация всегда создаёт CUSTOMER | role в JSON не меняет роль |
| Подделка перехода статуса | конечный автомат и блокировка заказа | COMPLETED → CANCELLED → 409 |
| Утечка пароля | bcrypt; пароль не возвращается API | проверка БД и ответа |
| Отсутствие аудита заказа | audit_logs внутри той же транзакции | rollback не оставляет частичный audit |

## Тест-кейсы для ручной интеграционной проверки PostgreSQL

1. GET `/health` при доступной БД → 200.
2. POST register с валидными данными → 200.
3. Повтор email → 409.
4. Пароль короче 8 символов → 400.
5. Login с правильным паролем → 200.
6. Login с неверным паролем → 401.
7. `/api/me` без JWT → 401.
8. `/api/me` с валидным JWT → 200.
9. Регистрация с `role=ADMIN` не даёт роль ADMIN.
10. CUSTOMER вызывает POST `/api/games` → 403.
11. Добавление несуществующей игры в корзину → 409.
12. Оформление пустой корзины → 400.
13. Подмена `total_cents` в JSON не влияет на сумму; поле неизвестно и отклоняется.
14. CUSTOMER A запрашивает заказ CUSTOMER B → 404.
15. CUSTOMER вызывает `/api/admin/audit` → 403.
16. ADMIN вызывает `/api/admin/audit` → 200.
17. Пагинация limit=1000 ограничивается 100.
18. sortBy с SQL-фрагментом не исполняется и использует сортировку по умолчанию.
19. Повтор старого refresh после ротации → 401.
20. Одновременное оформление последней копии одной игры: только один заказ может списать остаток.
21. Отмена заказа из NEW/PAID/PROCESSING возвращает остатки.
22. Отмена COMPLETED или повторная отмена → 409.

## Команды для фактических доказательств

```powershell
go test ./...
go test -race ./...
go vet ./...
curl.exe -i http://localhost:8080/health
```

Сохранить stdout/stderr этих команд и реальные HTTP-ответы в `evidence/`. Этот файл является планом, а не подменой фактических логов.
